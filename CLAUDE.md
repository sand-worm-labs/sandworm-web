# Agent instructions

- Write as little code as possible; this is the top priority. Before writing a helper, reach for what is already there: a package already in the repo (`date-fns`, `zod`, `cn` from `@sandworm/ui`), a platform built-in (`Intl`, `Map.groupBy`), or an existing shared component. Delete code a package or built-in makes redundant, and do not add a new dependency for a few lines.
- No per-file constants for things that already exist or are used once. Before adding a module-level `const`, grep the repo: if the value, string or regex is already declared anywhere, import it instead of declaring it again (`DAY` is declared 14 times and `TEAM_ONLY` twice, which is the mistake to avoid). Shared values go in `@sandworm/types` or one shared util, not copied into each file. A value used once is written inline, not hoisted to a named constant. Use `date-fns` (`subDays`, `differenceInDays`) instead of `n * 24 * 60 * 60 * 1000` arithmetic. A constant that is kept gets a specific name (`KPI_KEY_PATTERN`, not `KEY`).
- Mock and seed data is code too, so keep it small and non-repeating. Do not copy a fixture file per variant (org type, client, tab); write one template and pass what differs. Store raw values (numbers, ISO dates, enums) and let the real formatters produce the text (`buildKpi`, `formatKpiValue`, `lib/dates.ts`), never hand-typed `"▲ 7%"`, `"positive"`, `"1.42M"` or `"Mon 14:10"`. State a fact once and derive the rest from it, so the same number is not retyped in a KPI, a briefing item and a signal. Three or four rows per list is enough. Use one generic builder, not one identical builder per entity.
- `apps/web` is the standard for every other app, including `apps/terminal`. No new standards: do it the way web does it, with the same package, pattern, folder and file naming (data comes from codegen'd `.graphql` queries and their Apollo hooks, not from hand-written query strings or per-feature mapper files). Before building something in the terminal, find how web does it first. If web has no precedent, say so and ask rather than inventing a pattern. Differ from web only when the terminal truly cannot do it web's way, and tell the user why.
- Do not add a `Co-Authored-By: Claude` trailer, or any "Generated with Claude Code" line, to commit messages or pull request descriptions.
